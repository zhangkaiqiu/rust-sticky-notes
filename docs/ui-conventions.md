# 几何与交互约定

> 这份文档记录**已经踩过的坑**和对应的硬性规则。新增 UI 时先读一遍，
> 比事后调 bug 便宜得多。

这个应用的问题几乎都出在同一个地方：**同一件事有两个以上的事实源**。
一旦两个源不同步，就会出现"展开时好好的、折叠就跳""拖动时有死区"这类 bug，
而且修一处漏一处。下面每条规则都是把这个"源"收敛成一个。

---

## 1. 高度只有一个源：`BAR_HEIGHT`

标题栏的高度和折叠态窗口的高度**必须是同一个数值**，否则展开↔折叠时
标题会上下跳（用户反馈过两次）。

- 前端事实源：[`src/components/TopBar.tsx`](../src/components/TopBar.tsx) 导出的 `BAR_HEIGHT`
- 后端事实源：[`src-tauri/src/lib.rs`](../src-tauri/src/lib.rs) 的 `COLLAPSED_HEIGHT`

两边都是 **40**。改一个必须改另一个。

**禁止**在别处再写字面量高度。曾出现过的错误写法：

```tsx
// ❌ 浮动按钮组自己写了 36px，和标题栏的 40px 差 4px，折叠切换时整组图标上下跳
className={`... ${collapsed ? "inset-y-0" : "top-0 h-9"}`}

// ✅ 引用同一常量，没有任何 collapsed 分支
style={{ height: BAR_HEIGHT }}
className="absolute right-1 top-0 z-20 flex items-center gap-0.5"
```

**判断标准**：同一个组件里如果出现 `collapsed ? A : B` 并且 A/B 影响几何
（高度、位置、内边距），基本就是 bug 的来源。配色、文案、图标方向可以分支，
**几何一律不许分支**。

---

## 2. 整条标题栏都要能拖动

`data-tauri-drag-region` 的两个特性（都不是直觉能猜到的）：

1. **不继承**。Tauri 只检查鼠标按下时命中的那个元素有没有该属性。
2. 子元素若不带，它盖住的那块区域就**拖不动**，表现为"标题栏中间一大片死区"。

所以规则是：

| 元素类型 | 是否带 `data-tauri-drag-region` | 额外处理 |
|---|---|---|
| 纯展示 / 占位 / 文字（标题、保存提示、空白块） | ✅ 必须带 | — |
| 按钮等有点击行为的元素 | ❌ 不带 | `onMouseDown` 里 `stopPropagation()`，防止按下即被当成拖动 |

新增标题栏元素时照此办理。**不要**指望父级带了自己就能继承。

---

## 3. 浮层一律用独立窗口，不靠"画到窗口外"

WebView 的 DOM **无法绘制到窗口边界之外**。这是技术栈的硬限制，
不是代码没写好——换框架也改变不了，除非换到有原生 Popup 的桌面框架。

由此产生两条规则：

1. **设置面板 = 独立窗口**（`settings-<noteId>`，见 `settings_panel.rs`）。
   它不受便签尺寸约束，折叠成 40px 的条也能完整显示，永远不需要滚动条。
2. **折叠态不弹右键菜单**。折叠窗口只有 40px 高，菜单必然被裁掉，
   而且折叠态只有一个标题、没有可操作项，弹出来也没有意义。

### 为什么不用"放大窗口 + 透明留白"

曾考虑过把便签窗口临时撑大、面板画在透明区里。否决原因是**透明区照样捕获鼠标**：
`pointer-events: none` 只影响 DOM，不影响窗口本身；真正要穿透得用
`set_ignore_cursor_events`，而它是**整窗开关**，只能跟着鼠标位置反复切换，
结果是鼠标移到面板上要先被穿透、晃一下才响应。

---

## 4. 跨窗口状态：以后端为准，变更即广播

多窗口（每条便签的 `note-*` + 它的 `settings-*`）各自持有 React 状态。
不通知就会累积出这些 bug（都真实发生过）：

- 面板改了配色，便签窗口不刷新 → 用户以为没生效；
- 面板被关掉，便签的齿轮按钮还以为它开着 → 点一次没反应；
- 便签拖动，面板不跟 → 松手后才瞬移。

规则见 [`events.rs`](../src-tauri/src/events.rs)：

| 事件 | 触发时机 | 监听方 |
|---|---|---|
| `note-updated` | 标题 / 外观变了 | 便签窗口、面板窗口各自重读 |
| `settings-state` | 面板开 / 关 | 便签窗口同步齿轮高亮 |

**开关状态不许前端猜**。齿轮按钮调 `toggle_settings_panel`，由后端按
"窗口是否存在"决定开还是关——本地 state 可能是过期的。

**跟随类动作挂在窗口事件上，不挂在落盘防抖上**。面板跟随挂在
`WindowEvent::Moved` 上立即执行；若挂在 400ms 的持久化防抖里，
拖动时面板不动、松手才瞬移。

---

## 5. 层级：面板跟着便签走，不无条件置顶

- 便签置顶 → 面板也置顶（否则面板会被便签盖住）
- 便签不置顶 → 面板也是普通窗口，**被别的应用盖住是正常行为**

不要写死 `always_on_top(true)`。曾经这么写，结果"便签没钉住，面板却永远飘在最上面"。

---

## 6. 功能入口去重

同一个功能只保留一个入口，否则用户会在两处看到同一个开关，行为还可能不一致。

| 功能 | 唯一入口 |
|---|---|
| 折叠 / 展开 | 标题栏左侧箭头 |
| 置顶 | 卡片右上角图钉 |
| 设置面板 | 卡片右上角齿轮 |
| **改名** | **设置面板顶部的标题输入框** |
| 删除便签 | 设置面板 |
| 隐藏到托盘 | 设置面板 |
| 新建便签 | 右键菜单 |

曾经在右键菜单里重复列过"折叠 / 设置 / 删除"，在设置面板里重复过"窗口置顶"，
都已删除。

---

## 7. 标题不可编辑，只负责显示和拖动

标题是纯 `<span>`，没有 hover 底色、没有点击行为。原因：
"hover 看起来能点、点了却没反应"是明确的错误暗示，用户已经抱怨过。

改名统一在设置面板里做。这样标题区域的行为极其单纯：左键拖动、右键弹菜单。
